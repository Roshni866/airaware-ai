# AirAware AI — Implementation Report

Redesign of AirAware AI from a 3-tab research demo into a polished, functional,
deployment-ready application. Covers what was built, what was preserved, how it was
tested, known limitations, and exact run/deploy instructions.

## 1. Summary

The existing PM2.5 forecasting project (Random Forest, feature set C, split-conformal
90% intervals) was **not** rebuilt or retrained. On top of it: a UI redesign to the
specified climate-tech palette, a live-data integration layer (OpenAQ v3, fails
honestly without a key), an automated refresh pipeline (GitHub Actions), an
uncertainty-aware 3-tier alert built from the existing conformal interval, and a
preserved, unaltered research-results page.

The app has 4 pages: Overview, Live Air Quality, PM2.5 Forecast, Model Performance.
AQI is computed automatically wherever live pollutant readings are available
(`src/aqi.py`) — there is no standalone manual-entry calculator page, and data-source/
limitations detail lives here and in the README rather than as an in-app page, by
request.

## 4. Features implemented

- **UI:** exact palette via a custom design system; hero section; metric cards sourced
  correctly ("Data unavailable" rather than invented, when no live key is configured);
  interactive Plotly charts (historical/forecast/interval/threshold, all labeled).
- **Live data:** OpenAQ v3 two-call client (sensors → latest), CO ppm→mg/m³ conversion,
  freshness classification (Fresh <3h / Delayed <24h / Stale ≥24h / Unavailable), never
  fabricates a reading.
- **Refresh pipeline:** `src/refresh.py` runs data_pipeline → features → predict, logs
  every run to `results/refresh_log.jsonl`, updates `results/last_refresh.json` only on
  success, never imports or calls `src.train` (asserted by a dedicated test). Scheduled
  via GitHub Actions (`.github/workflows/refresh.yml`) rather than Streamlit Community
  Cloud, which has no reliable background scheduler.
- **AQI:** CPCB breakpoints for all 8 pollutants, linear sub-index interpolation, honest
  flagged extrapolation beyond the officially open-ended Severe band, the
  ≥3-pollutants-with-PM2.5-or-PM10 coverage rule for an overall AQI — applied
  automatically to live readings on the Overview and Live Air Quality pages.
- **Forecast:** confirmed (not assumed) the served model is RF/feature set C by reading
  `results/selected_model.json` and the model bundle directly; 3-tier uncertainty-aware
  alert built on the existing conformal interval (not a new algorithm); stale-data
  handling shows the last valid prediction with its real origin timestamp.
- **Performance page:** all pre-registered evaluation numbers rendered directly from
  `results/*`, never recomputed.
- **Architecture:** business logic in `src/`, UI in `ui/`, `app.py` a thin dispatcher;
  `st.cache_data`/`st.cache_resource` used appropriately; no training on any dashboard
  load or scheduled refresh.

## 5. Data sources and limitations

(Consolidated here and in the README rather than as an in-app page.)

- **Historical PM2.5:** OpenAQ archive (bulk historical dumps), New Delhi-8118. Hourly,
  aggregated to a local-day mean requiring ≥18/24 valid hours. This archive has its own
  publishing lag of a few days — a refresh will not necessarily land exactly on today's
  date, which is expected, not a bug.
- **Live PM2.5 / other pollutants:** OpenAQ v3 API, same station — requires
  `OPENAQ_API_KEY`.
- **Weather (model feature):** Open-Meteo Historical Weather API — observed/reanalysis
  values, not the forecasts that would have been available at prediction time (see
  REPORT.md's `C_oracle` diagnostic for how much this could matter).
- Single station, single city — results don't generalize elsewhere.
- ~19% of historical days are missing, concentrated in a few long gaps (worst: 2022).
- Conformal coverage is empirical, measured once — not guaranteed under future drift.
- The forecast is PM2.5 in µg/m³, not an overall CPCB AQI.
- No direct, matched comparison to CPCB/SAFAR/IQAir forecasts — no accuracy-superiority
  claim is made.

Live stats (coverage %, last archived day, longest gap) are in
`results/data_quality.md` / `.json`, regenerated by every refresh.

## 7. Bugs found and fixed

1. **Fabricated CPCB Severe-band upper bounds** (caught before delivery): an early draft
   invented upper bounds for the Severe category; verified against CPCB's actual 2014
   table (officially open-ended) and rewrote the calculator to flag honest extrapolation.
2. **CSS specificity bug:** hero heading rendered dark-on-dark; fixed with `!important`
   + descendant selectors.
3. **Plotly `update_layout()` TypeError:** a `legend` key in the shared template
   collided with each chart's own `legend=` kwarg; removed from the shared template.
4. **Streamlit `st.form()` reactivity bug:** the former AQI Calculator's checkboxes
   couldn't reactively enable their number inputs inside a form (forms only commit on
   submit); fixed by removing the form wrapper.
5. **Dark-mode theme clash (found post-delivery, by the project owner):** with the
   viewer's OS/browser set to dark mode, Streamlit's native widgets (checkboxes, number
   inputs, `st.warning`/`st.info` boxes) auto-themed dark while the app's custom CSS
   still forced dark text everywhere — producing unreadable dark-on-dark text and solid
   black checkboxes. Fixed with `.streamlit/config.toml` forcing `base = "light"`,
   which controls Streamlit's own widget theming independent of the custom CSS.
   Verified fixed under a forced `color_scheme: dark` browser context.

## 8. Honest caveats

- The cached historical archive ends a few weeks before "today" at any given moment,
  by design — the forecast is generated from the archive, not computed live each page
  load. Running `python -m src.refresh` pulls the latest available archive data, but
  the archive's own publishing lag (a few days) means it won't necessarily reach all
  the way to today even after a refresh.
- No historical backfill beyond what the archive provides was performed — out of scope
  per "do not retrain/re-download unnecessarily."

## 9. Local run

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
export OPENAQ_API_KEY="your-key-here"               # optional, enables live data
streamlit run app.py
```

## 10. Deployment (GitHub + Streamlit Community Cloud + GitHub Actions)

```bash
git init
git add .
git commit -m "AirAware AI: redesigned application"
git branch -M main
git remote add origin <your-repo-url>
git push -u origin main
```

1. Add `OPENAQ_API_KEY` as a GitHub Actions secret on the repo (**Settings → Secrets
   and variables → Actions**) so `.github/workflows/refresh.yml` can fetch live data
   during its daily scheduled run (cron `17 3 * * *`, plus manual `workflow_dispatch`).
2. [share.streamlit.io](https://share.streamlit.io) → New app → this repo/branch →
   entry point `app.py`.
3. App **Settings → Secrets** → add `OPENAQ_API_KEY = "your-key-here"`.
4. Deploy.

With step 1 done, the scheduled workflow keeps the deployed app's data current
automatically — no manual refresh or always-on machine required.
